A RAG system can tell no evidence from some evidence — but not good evidence from bad

Corrupting retrieval halved accuracy without producing a single extra fabrication. Only when the evidence was removed outright did the system notice, abstaining on 92% of questions.

Study in progress Noise sweep complete · 5 levels 0 invalid generations Hypotheses preregistered Judge ≠ generator
Through 75% corruption, correct answers fell from 96 to 78 of 150 while unsupported assertions stayed at 7, 6, 7, 7. At 100% corruption abstention jumped from 38% to 92% — the safety response is a threshold, not a gradient.
Δ accuracy at 75% corruption −12.0 pts [−18.0, −7.3] · p < 0.0001
Δ hallucination at 75% corruption ±0.0 pts [−2.7, +2.7] · p = 1.00
Δ abstention at 100% corruption +62.9 pts [+53.0, +71.2] · p < 0.0001

All figures are paired bootstraps over the same questions, so per-question difficulty cancels. The hallucination result is not a weak trend — it is a null bounded within ±2.7 points, measured against an accuracy collapse four times that size.

Why this matters practically: partial retrieval failure is the costly regime, but not for the usual reason. It does not provoke fabrication. It goes undetected — accuracy halves while the system keeps answering at nearly the same rate, showing no outward sign that anything is wrong.

Read the red band across all five rows: it is the same width in every one, and narrowest at the bottom. It is the only failure mode that misleads a user, and corrupting retrieval never widened it.

The bottom row is the mechanism. Between 0% and 75% the blue band creeps from 44 to 57 — the system barely reacts. Remove the evidence entirely and it flips to 122. Abstention is triggered by the absence of evidence, not by its quality.

This is invisible to any analysis that scores answers as merely right or wrong. A pooled report says failures rose from 54 to 72 and stops. Separating an unsupported assertion from a faithful report of bad evidence is what makes the null visible — and that separation was the study's central design decision.

Can failure be predicted before generation?

A similarity gate works, but only above a cost threshold

Retrieval scores exist before the generator is called, so a system could refuse in advance rather than answer badly. The strongest signal reaches AUROC 0.687 for predicting an unsupported assertion — above chance, and enough to gate on.

Whether gating is worth it depends on how much worse a fabrication is than a refusal, which is a property of the application rather than the model. Sweeping that cost ratio gives a deployment rule:

C < 5answer everything — no threshold beats it
C = 5gate at 0.44, answer 83% of questions
C = 10gate at 0.57, answer 54%
C = 20gate at 0.62, answer 38%

C is the cost of one fabrication expressed in units of one correct answer. Below 5×, a retrieval-score gate destroys more value than it protects.

Validity

Does the synthetic corruption match real failure?

The perturbation is artificial, so the obvious objection is that none of it describes retrieval failing on its own. The clean condition answers it: 53 questions where the right document simply was not retrieved, no intervention at all.

Integrity

What this does not show

The preregistered hypothesis was only half right

We predicted silent failure would peak at partial corruption. Observed: 0.185, 0.203, 0.219, 0.208, 0.069 — there is an interior peak, but only the collapse at 100% is significant. The rising limb sits inside intervals of [0.09, 0.30] and [0.12, 0.33] that overlap completely. A power analysis run before data collection said separating a peak at n=150 needs a gap above 16 points; the observed rise is 3. Reported as partially supported at best — and the abstention series describes the mechanism better than the derived ratio does.

Bounds on the claim

  • One generator, one retriever, one noise type — related only
  • n=150 (n=132 at 100%); unsupported counts of 1–7 make the level imprecise even where the difference is tight
  • Retrieval is a 384-dimension local model, so absolute accuracy is not comparable to SQuAD leaderboards
  • Context-size and mitigation experiments are still collecting
Method

How it was measured

600 SQuAD v2 questions (70% answerable / 30% unanswerable, seed 20240617) over a 1,330-chunk corpus built from all 1,204 development paragraphs. Corruption is applied to the context handed to the generator, never to the shared index — so the dose each individual answer received is exact and known, which a poisoned index cannot give you.

Generation and judging use different models, so faithfulness verdicts are not self-evaluation. Retrieval runs locally, making that half of the pipeline reproducible without an API key.

Generatorgemini-3.5-flash-lite, temperature 0
Judgegemini-3.1-flash-lite — different model, self_eval: false
Retrieverall-MiniLM-L6-v2, exact inner product over FAISS
StatisticsPaired bootstrap, 2000 resamples, clustered by question
